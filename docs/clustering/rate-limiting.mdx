The `ratelimit` package is a small, cluster-wide rate limiter built directly on top of [`ActorSystem.KV()`](/clustering/kv-store). A limit configured on a `ratelimit.Limiter` holds across every node in the cluster: whichever node handles a given request, the shared counter for its key is the same one every other node reads and writes.

<Note>
Per-node limiters multiply the effective limit by the replica count and drift under autoscaling. `ratelimit.Limiter` avoids both problems by keeping exactly one counter per key in the cluster registry, instead of one counter per node.
</Note>

## Algorithm

`ratelimit.Limiter` implements a **fixed-window counter**: for a given key, every request that lands within the same `Window`-sized slice of wall-clock time shares one counter, capped at `Limit`. The counter is created with `Store.PutIfAbsent` — which also acts as its own cleanup, since the entry's TTL expires it once the window elapses — and incremented under a short-lived `Store.TryLock` so concurrent callers (same node or different nodes) serialize on the same counter instead of racing a read-modify-write.

<Warning>
Fixed-window counters have a well-known boundary effect: a burst of requests that straddles the boundary between two windows can admit close to `2 x Limit` requests in the worst case (up to `Limit` at the end of one window, and up to `Limit` again right after the next window starts). Budget for that tolerance, or use a smaller `Window` to bound how large the effect can be in absolute terms.
</Warning>

## Creating a Limiter

```go
import (
    "time"

    "github.com/tochemey/goakt/v4/ratelimit"
)

store, err := system.KV()
if err != nil {
    // ErrActorSystemNotStarted or ErrClusterDisabled
    return err
}

// at most 100 requests per key, per 1-second window, cluster-wide.
limiter, err := ratelimit.New(store, 100, time.Second)
if err != nil {
    return err
}
```

`New` rejects a nil store (`ratelimit.ErrNilStore`), a non-positive limit (`ratelimit.ErrInvalidLimit`), and a non-positive window (`ratelimit.ErrInvalidWindow`).

## Allow and AllowN

```go
ok, err := limiter.Allow(ctx, "api-key:acme-corp")
if err != nil {
    return err
}
if !ok {
    // deny the request; the key is over its limit for the current window
    return ErrTooManyRequests
}
```

`AllowN` charges `n` units of the same per-key, per-window budget in one call, useful for weighted requests:

```go
// this request is worth 5 units of the budget.
ok, err := limiter.AllowN(ctx, "api-key:acme-corp", 5)
```

A call that would exceed the remaining budget is denied outright — it never partially consumes it, so a later, smaller request can still succeed against what is left.

## Degradation outside cluster mode

Because `Limiter` is built directly on `kv.Store`, it inherits the same typed errors: outside cluster mode (or before the actor system has started), the `Store` methods `Limiter` calls return `gerrors.ErrClusterDisabled` / `gerrors.ErrActorSystemNotStarted`, and `Allow`/`AllowN` propagate them unchanged.

```go
ok, err := limiter.Allow(ctx, "api-key:acme-corp")
if errors.Is(err, gerrors.ErrClusterDisabled) {
    // no cluster-wide limiter available; fall back to a local decision or fail open/closed
}
```

## Tuning lock contention

Two options tune how `AllowN` behaves when it loses the race to acquire a key's counter lock to another concurrent caller:

```go
limiter, err := ratelimit.New(store, 100, time.Second,
    ratelimit.WithLockTTL(2*time.Second),      // how long the counter lock may be held
    ratelimit.WithMaxRetries(20),              // attempts before giving up
    ratelimit.WithRetryBackoff(5*time.Millisecond), // pause between attempts
)
```

Once the retry budget is exhausted, `AllowN` returns `ratelimit.ErrLimiterBusy` — a contention signal distinct from a rate-limit denial (`ok == false, err == nil`).

## Reference

| Function/Method                        | Purpose                                                                 |
|------------------------------------------|--------------------------------------------------------------------------|
| `ratelimit.New(store, limit, window, opts...)` | Create a `Limiter` bound to a `kv.Store`.                          |
| `limiter.Allow(ctx, key)`                | Admit a single request for `key`; equivalent to `AllowN(ctx, key, 1)`.   |
| `limiter.AllowN(ctx, key, n)`             | Admit `n` units of budget for `key` in one call.                        |
| `ratelimit.WithLockTTL(d)`                | Override how long the internal counter lock may be held (default 2s).   |
| `ratelimit.WithMaxRetries(n)`             | Override the counter lock retry budget (default 20).                    |
| `ratelimit.WithRetryBackoff(d)`           | Override the pause between lock retry attempts (default 5ms).           |
